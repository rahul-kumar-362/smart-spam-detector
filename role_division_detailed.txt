DETAILED RESPONSIBILITIES & IMPLEMENTATION LOGIC:

1. Data Engineering & Pipeline (`merge_data.py`)
   - Logic: You wrote a script to combine two disparate datasets (a local `dataset.csv` likely containing SMS spam, and `enron_emails.csv`).
   - Implementation Details:
     * Handled missing files gracefully (`FileNotFoundError`).
     * Standardized headers (mapping 'v1'/'v2' and 'spam'/'text' to a uniform 'label' and 'text').
     * Converted numeric labels (1/0) from the Enron dataset to categorical strings ('spam'/'ham').
     * Removed duplicates and shuffled the dataset (`frac=1, random_state=42`) to prevent the model from learning the order of the datasets.

2. NLP Preprocessing (`text_preprocess.py`)
   - Logic: You needed to clean raw email text before feeding it to the model.
   - Implementation Details:
     * You intentionally avoided heavy libraries like NLTK to make the application lightweight and easier to deploy in constrained cloud environments.
     * Built a custom, hardcoded set of 74 common English stopwords.
     * Used Regex (`re.sub(r'[^a-z\s]', ' ', text)`) to remove all special characters and numbers, keeping only lowercase alphabets.
     * Normalized whitespace by removing extra spaces.

3. Model Training (`train.py`)
   - Logic: Converting text to numbers and training a classifier.
   - Implementation Details:
     * Used Scikit-Learn.
     * Feature Extraction: Implemented `TfidfVectorizer` (Term Frequency-Inverse Document Frequency) limited to the top 5,000 features (`max_features=5000`) to balance accuracy and memory usage.
     * Algorithm: Chose `MultinomialNB` (Naive Bayes), which is mathematically well-suited for discrete data like word counts/frequencies in text classification.
     * Split data 80/20 for training/testing.
     * Achieved high accuracy (~96.68%).
     * Serialized the model and vectorizer using `pickle` so it can be loaded into memory instantly by the API without retraining.

4. Backend API & Hybrid Scoring System (`api.py`)
   - Logic: You built the bridge between the ML model and the frontend, but you didn't just return the raw model prediction. You built a "Hybrid Scoring System."
   - Implementation Details:
     * Framework: Flask with Flask-CORS to allow the Chrome extension to make cross-origin requests.
     * Endpoint: Created a `POST /predict` endpoint that accepts JSON.
     * Trigger Word Detection: Implemented regex with word boundaries (`r'\b' + re.escape(word) + r'\b'`) against a list of ~70 spam trigger words (e.g., "urgent", "winner"). The word boundaries ensure that "free" triggers, but "freedom" does not.
     * Hybrid Logic (The smartest part of the backend):
       - Signal 1 (Model): Gets the raw probability from Naive Bayes (`model.predict_proba`).
       - Signal 2 (Context): If the Chrome extension reports that Gmail itself flagged the email as spam (`gmail_spam=True`), and the model was weakly predicting 'ham' (prob < 0.92), you override it and classify it as spam, boosting the confidence.
       - Signal 3 (Triggers): If the model predicts 'ham', but there are 2 or more trigger words, you calculate "trigger density". If density is high enough, you override the model and classify as spam.
     * Error Handling: Added robust try-except blocks to catch empty text or missing fields, returning proper 400/500 HTTP status codes.

5. Deployment Configuration (`build.sh`, `requirements.txt`, etc.)
   - Wrote a bash script (`build.sh`) to automate dependency installation and model retraining.
   - Configured Gunicorn in `Procfile` for production deployment.

- "I wrote a custom NLP preprocessor without NLTK. I did this deliberately because cloud providers often limit slug sizes, and removing the heavy NLTK dependency made our API much faster to deploy."

DETAILED RESPONSIBILITIES & IMPLEMENTATION LOGIC:

1. Extension Architecture (`manifest.json` & `background.js`)
   - Logic: Setting up a modern, secure browser extension.
   - Implementation Details:
     * Upgraded to Manifest V3 standards (mandatory for modern Chrome extensions).
     * Configured permissions: `activeTab` (to read current page), `storage` (for history/settings), and host permissions strictly for `https://mail.google.com/*`.
     * Implemented a Background Service Worker (`background.js`) that acts as a secure middleman. It receives the email text from the content script, fetches the API URL from local storage, makes the `fetch()` call to the Flask backend, and returns the result.

2. Gmail DOM Injection (`content.js` & `content.css`)
   - Logic: This is the hardest part of the frontend. Gmail is a complex Single Page Application (SPA) where the URL changes but the page doesn't reload.
   - Implementation Details:
     * Polling Loop: Implemented `setInterval` to constantly check the URL hash (e.g., `#inbox/FMfcgzQXK...`) and DOM elements (`div.a3s`) to detect exactly when a user opens an email.
     * UI Injection: Dynamically creates and injects a floating "Check Spam" button (`#ssd-floating-btn`) into the Gmail DOM.
     * Email Extraction Engine (Robust Fallbacks): Gmail's DOM changes. You wrote 4 different strategies to extract the text:
       1. Look for `div.a3s.aiL` (most reliable).
       2. Look for `.ii.gt` wrapper.
       3. Look for `[data-message-id]`.
       4. Fallback to the main ARIA role area.
     * Noise Reduction: Wrote logic to strip out Gmail's UI text that gets accidentally copied (e.g., "Reply", "Forward", "Report spam").
     * Signal Gathering: Wrote functions to read Gmail's UI state. `isInSpamFolder()` checks if the URL has "spam" or if Gmail is displaying a phishing warning banner. This crucial data is sent to the backend.
     * In-Page Overlay: Injected a beautifully styled (`content.css`) overlay directly inside Gmail to show the results (Confidence bar, Trigger words) without making the user open the extension popup.

3. Extension Popup UI (`popup.html`, `popup.css`, `popup.js`)
   - Logic: A standalone interface for manual scanning, history, and settings.
   - Implementation Details:
     * Styling: Implemented a highly premium "Dark Glassmorphism" UI. Used CSS variables, backdrop filters (`backdrop-filter: blur`), animated gradients, and floating orbs to make it look futuristic.
     * Tab System: Built a custom vanilla JS tab navigator (Scan, History, Settings).
     * State Management: Used `chrome.storage.local` to persistently save the API URL (Settings tab) and the last 20 scanned emails (History tab).
     * Real-time validation: Character counters and button shake animations for empty inputs.

4. Streamlit Dashboard (`app.py`)
   - Logic: Built a secondary, web-based dashboard for users who don't want to install the extension.
   - Implementation Details:
     * Utilized Streamlit's session state (`st.session_state`) to track the number of predictions made in that session.
     * Implemented custom HTML/CSS within Streamlit (`st.markdown(..., unsafe_allow_html=True)`) to override default styles and create colored result boxes.
     * Added an "Explainable AI" section that highlights exactly which trigger words were found in the user's text.
     * Built a mock analytics dashboard showing precision/recall metrics.
